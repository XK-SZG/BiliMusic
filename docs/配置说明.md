# BiliMusic 配置说明

本文档说明 `config.yaml` 配置文件中各项参数的含义和使用方法。

## 配置文件位置

配置文件位于项目根目录：`config.yaml`

修改配置后需要重启应用才能生效。

---

## 配置项说明

### 服务器配置 (server)

```yaml
server:
  host: "127.0.0.1"  # 后端服务监听地址
  port: 12180        # 后端服务端口
  debug: false       # 是否启用调试模式
```

#### host
- **类型**：字符串
- **默认值**：`127.0.0.1`
- **说明**：后端服务监听的 IP 地址
- **建议**：保持 `127.0.0.1`（仅本地访问），不要设置为 `0.0.0.0`（允许外部访问）以确保安全

#### port
- **类型**：整数
- **默认值**：`12180`
- **说明**：后端服务监听的端口号
- **建议范围**：10000-65535
- **注意**：修改端口后，前端代码中的 API 地址也需要相应修改

#### debug
- **类型**：布尔值
- **默认值**：`false`
- **说明**：是否启用调试模式
- **影响**：
  - `true`：启用详细日志输出，便于开发调试
  - `false`：正常日志级别，适合生产环境

### 存储配置 (storage)

```yaml
storage:
  download_path: "backend/data/downloads"  # 视频缓存目录
  cache_limit_gb: 10                       # 缓存上限 (GB)
```

#### download_path
- **类型**：字符串
- **默认值**：`backend/data/downloads`
- **说明**：视频缓存文件的存储目录
- **支持**：相对路径或绝对路径
- **注意**：
  - 相对路径相对于项目根目录
  - 确保目录有足够的磁盘空间
  - 目录会自动创建（如果不存在）

#### cache_limit_gb
- **类型**：整数
- **默认值**：`10`
- **单位**：GB（千兆字节）
- **说明**：视频缓存的最大容量限制
- **行为**：当缓存超过此限制时，系统会自动清理最旧的缓存文件
- **建议**：根据可用磁盘空间设置，建议至少 5GB

---

### 调度器配置 (scheduler)

```yaml
scheduler:
  cleanup_interval_hours: 6  # 自动清理间隔（小时）
```

#### cleanup_interval_hours
- **类型**：整数
- **默认值**：`6`
- **单位**：小时
- **说明**：自动清理任务的执行间隔
- **清理内容**：
  - 孤立的缓存文件（数据库中已删除但文件仍存在）
  - 超过缓存上限的旧文件
- **建议**：6-24 小时之间

---

### 下载配置 (download)

```yaml
download:
  max_workers: 3              # 并发下载线程数
  max_retries: 3              # 下载失败最大重试次数
```

#### max_workers
- **类型**：整数
- **默认值**：`3`
- **说明**：同时进行下载的最大线程数
- **影响**：
  - 数值越大，下载速度越快，但占用资源越多
  - 数值越小，下载速度越慢，但系统负载越低
- **建议范围**：1-5
- **注意**：过高的值可能导致网络拥塞或被 B 站限流

#### max_retries
- **类型**：整数
- **默认值**：`3`
- **说明**：下载失败后的最大重试次数
- **行为**：超过重试次数后，任务标记为失败
- **建议范围**：2-5

---

### 数据库配置 (database)

```yaml
database:
  pool_size: 20               # 连接池大小
  max_overflow: 40            # 最大溢出连接数
  pool_timeout: 10            # 获取连接超时（秒）
  pool_recycle: 1800          # 连接回收时间（秒）
```

#### pool_size
- **类型**：整数
- **默认值**：`20`
- **说明**：数据库连接池的常驻连接数
- **影响**：影响并发数据库操作的性能
- **建议**：保持默认值，除非遇到连接不足的问题

#### max_overflow
- **类型**：整数
- **默认值**：`40`
- **说明**：连接池满时允许创建的额外连接数
- **计算**：最大总连接数 = pool_size + max_overflow = 60
- **建议**：保持默认值

#### pool_timeout
- **类型**：整数
- **默认值**：`10`
- **单位**：秒
- **说明**：等待获取数据库连接的超时时间
- **行为**：超时后抛出异常
- **建议**：5-30 秒之间

#### pool_recycle
- **类型**：整数
- **默认值**：`1800`
- **单位**：秒（30 分钟）
- **说明**：数据库连接的回收时间
- **作用**：防止长时间闲置的连接失效（如系统睡眠后）
- **建议**：1800-3600 秒之间

## 配置示例

### 低配置设备

```yaml
server:
  host: "127.0.0.1"
  port: 12180
  debug: false

storage:
  download_path: "backend/data/downloads"
  cache_limit_gb: 5  # 减少缓存上限

scheduler:
  cleanup_interval_hours: 12  # 延长清理间隔

download:
  max_workers: 1  # 减少并发数
  max_retries: 2

database:
  pool_size: 10
  max_overflow: 20
  pool_timeout: 10
  pool_recycle: 1800
```

### 高性能设备

```yaml
server:
  host: "127.0.0.1"
  port: 12180
  debug: false

storage:
  download_path: "D:/BiliMusic/cache"  # 使用独立磁盘
  cache_limit_gb: 50  # 增加缓存上限

scheduler:
  cleanup_interval_hours: 3  # 缩短清理间隔

download:
  max_workers: 5  # 增加并发数
  max_retries: 3

database:
  pool_size: 30
  max_overflow: 60
  pool_timeout: 10
  pool_recycle: 1800
```

## 常见问题

### Q: 修改配置后不生效？
A: 确保已重启应用。配置文件在应用启动时加载，运行中修改不会生效。

### Q: 如何恢复默认配置？
A: 删除 `config.yaml` 文件，应用会自动使用内置的默认配置。

### Q: 可以使用环境变量覆盖配置吗？
A: 当前版本不支持，计划在未来版本中添加。

### Q: 配置文件损坏怎么办？
A: 应用会自动检测并使用默认配置，同时在日志中输出警告信息。
