# BiliMusic 性能优化计划书

## 1. 当前性能瓶颈分析（重点：启动与响应速度）

经过对项目代码（前端 Vue3 + Vite，后端 FastAPI）的初步分析，发现以下可能影响启动速度和运行性能的瓶颈：

### 1.1 前端瓶颈 (Frontend)
*   **路由与组件全量同步加载**：`router.js` 中所有的视图组件（如 `Home`, `BiliLibrary` 等）以及 `App.vue` 中的重型组件（如 `ImmersivePlayer`, `AudioVisualizer`, `ParticleEngine`）均采用同步 `import`。这会导致首屏加载时 JavaScript Bundle 体积过大，延长白屏时间。
*   **静态资源内联过大**：`App.vue` 中直接内联了较大的 Base64 图片（如 `ICON_ANNUAL_VIP`），增加了主包体积。
*   **状态初始化阻塞**：`main.js` 中在路由挂载前同步读取 `localStorage` 并初始化 Store，虽然是为了解决特定问题，但如果逻辑复杂会轻微阻塞渲染。

### 1.2 后端瓶颈 (Backend)
*   **同步数据库迁移与初始化**：`main.py` 在全局作用域同步执行 `migrate_db.run_migrations()` 和 `create_all`。如果数据库较大，这会直接阻塞 FastAPI 应用的启动，导致前端请求超时。
*   **启动事件中的同步数据库操作**：`startup_event` 中执行了同步的数据库更新操作（重置下载状态），这同样会延长服务就绪时间。
*   **静态资源代理与缓存**：`/api/proxy/image` 接口虽然设置了 `Cache-Control`，但每次请求仍需经过 Python 代理，高并发下可能成为瓶颈。

## 2. 性能优化清单示例

以下是一些具体的优化手段示例：

*   [ ] **前端路由懒加载**：将 `import Home from './views/Home.vue'` 改为 `const Home = () => import('./views/Home.vue')`。
*   [ ] **前端组件异步加载**：使用 Vue 的 `defineAsyncComponent` 异步加载非首屏必需的重型组件（如 `AudioVisualizer`, `ParticleEngine`）。
*   [ ] **Vite 分包策略 (Chunking)**：在 `vite.config.js` 中配置 `build.rollupOptions.output.manualChunks`，将 `vue`, `pinia`, `vue-router` 等第三方库单独打包，利用浏览器缓存。
*   [ ] **后端数据库异步初始化**：将数据库迁移和表创建移至后台任务，或使用异步 SQLAlchemy 引擎。
*   [ ] **后端启动任务优化**：将 `startup_event` 中的耗时操作放入后台任务（BackgroundTasks）或异步执行，确保应用快速响应健康检查。

## 3. 分阶段可测试的性能优化计划

为了保证系统的稳定性，优化工作将分为三个阶段进行，每个阶段结束后均可进行独立测试。

### 阶段一：前端首屏加载优化（见效最快）
**目标**：显著降低前端首屏白屏时间，减小初始 JS 包体积。
**执行步骤**：
1.  **路由懒加载改造**：修改 `frontend/src/router.js`，将所有路由组件改为动态导入。
2.  **重型组件异步化**：修改 `frontend/src/App.vue`，使用 `defineAsyncComponent` 包装 `AudioVisualizer`, `ParticleEngine`, `ImmersivePlayer` 等非立即需要的组件。
3.  **资源抽离**：将代码中硬编码的大型 Base64 字符串提取到单独的静态资源文件中。
**测试验证**：
*   使用 Chrome DevTools 的 Network 面板，对比优化前后的初始 JS Bundle 大小。
*   使用 Lighthouse 测量 First Contentful Paint (FCP) 和 Time to Interactive (TTI) 指标。

### 阶段二：后端启动与响应优化
**目标**：加快 FastAPI 服务启动速度，防止启动时的阻塞导致前端请求失败。
**执行步骤**：
1.  **异步化启动任务**：将 `main.py` 中的 `migrate_db.run_migrations()` 和重置下载状态的数据库操作移至异步函数中，或在应用启动后通过后台线程/任务执行，不阻塞主事件循环。
2.  **数据库连接池优化**：检查并优化 SQLAlchemy 的连接池配置（如 `pool_size`, `max_overflow`），确保高并发下的响应速度。
**测试验证**：
*   记录后端进程从启动到输出 "Application startup complete" 的时间。
*   在后端启动瞬间，使用脚本模拟前端发送请求，验证是否会出现连接拒绝或超时。

### 阶段三：深度渲染与运行时优化
**目标**：提升播放时的帧率，减少内存占用，优化长列表性能。
**执行步骤**：
1.  **Vite 构建优化**：配置 `vite.config.js` 进行代码分割（Vendor Chunking），开启 Gzip/Brotli 压缩插件。
2.  **长列表虚拟化**：如果 `BiliLibrary` 或 `LocalLibrary` 中存在大量数据列表，引入虚拟列表（Virtual Scroller）组件，避免渲染过多 DOM 节点。
3.  **动画与特效节流**：检查 `AudioVisualizer` 和 `ParticleEngine` 的 `requestAnimationFrame` 逻辑，确保在页面隐藏或最小化时暂停渲染，节省 CPU/GPU 资源。
**测试验证**：
*   使用 Chrome DevTools 的 Performance 面板录制播放和切换页面时的性能，检查是否存在 Long Tasks。
*   加载包含 1000+ 首歌曲的列表，测试滚动流畅度。
